## 1. 목적
- 해결하려는 문제: 할일 관리는 보상이 약해서 꾸준히 쓰기 어렵다. 할일 완료로 얻은 포인트를 펫 돌보기에 쓰게 해서 계속 쓰고 싶게 만든다.
- 이 프로젝트로 보여주고 싶은 것 (포트폴리오 관점): 1인 개발로 Flutter 로컬 우선 앱을 완성하고, AI 생성 에셋 작업 흐름으로 그래픽 제작 비용을 줄인 사례.
- Phase 1에서는 핵심 순환(할일 → 포인트 → 펫)이 재미있는지 검증한다. Phase 2에서는 습관·성장·꾸미기로 계속 쓰고 싶게 만든다.

## 2. 대상 사용자와 핵심 시나리오
- 할일을 관리하며 가벼운 보상을 원하는 사용자
- 할일 등록 → 완료 → 포인트 적립 → 먹이 구매·급여 → 펫 반응 확인
- 습관을 이어 가며 스트릭 보너스를 받고, 펫을 키우고 홈을 꾸민다 (Phase 2)

### 3.1 할일 규칙
- 등록은 + 버튼의 등록 화면 하나로 한다(빠른 등록 입력창 없음): 제목, 종류, 난이도(기본 중), 카테고리(고정 8종 중 선택, 선택 항목), 날짜, 반복, 하위항목.
- 원타임 할일은 날짜가 필수다(기본 오늘).
- 반복은 매일 또는 요일 선택만 지원한다.
- 체크리스트는 원타임처럼 날짜를 갖고 이월된다. 하위항목은 진행률만 보여주고, 모두 체크하면 할일이 완료된다.
- 오늘 할일과 이월된 할일만 완료할 수 있다. 미래 날짜 원타임은 날짜를 오늘로 바꾸면 완료할 수 있다.
- 이월된 할일에는 "N일 지연"을 표시한다.
- 수정은 이후 회차에만 적용한다. 완료된 할일은 수정할 수 없고, 당일 취소한 뒤 수정한다. 반복 요일을 바꿔도 지난 기록과 스트릭은 그대로 둔다.
- 삭제해도 지난 기록과 지급된 포인트는 유지한다.

### 3.2 포인트 정산 규칙
- 잔액은 PointHistory 합계다.
- 시작 포인트는 0P.
- 일일 적립 상한은 100P(스트릭 보너스 포함). 오늘 적립 합계(취소 차감 반영)로 계산한다. 상한을 넘은 완료도 이력에 0P로 기록하고, 나중에 여유가 생겨도 소급해 올리지 않는다.
- 할일 회차(할일 + 날짜)마다 유효한 지급은 최대 1건이다. 스트릭 보너스도 같은 1건에 합쳐 지급한다. 완료를 취소하면 지급 당시 금액만큼 차감 이력(음수)을 남기고, 다시 완료하면 다시 지급한다.
- 완료 취소는 당일에만 할 수 있다. 차감으로 잔액이 음수가 될 수 있으며, 음수인 동안에는 구매할 수 없다.
- 반복 할일은 회차마다 지급한다.
- 체크리스트는 전체 완료 시 난이도 포인트를 한 번 지급한다.

### 3.3 펫 상태 규칙
- 이름은 1~10자.
- 기분·배고픔은 0~100이며 초기값은 80이다.
- 백그라운드 작업 없이, 앱을 열 때 마지막 갱신 시각부터 지난 시간으로 감소분을 계산한다. 감소량 등 수치는 decisions.md '제품 수치·규칙'을 따른다.
- 기분은 탭과 먹이로 오르고, 표정 표시에만 쓴다(3.5).
- 먹이는 상점 먹이 탭이나 홈 '돌보기'에서 구매하면 바로 활성 펫에게 급여한다(따로 보관하지 않는다). 먹이는 배고픔 회복·기분 상승·애정도를 준다.
- 배고픔이 100이면 먹이를 살 수 없다.
- 성장: 애정도(먹이·탭으로 누적, 감소 없음)가 50 이상이면 2단계, 150 이상이면 3단계(3.7). 4~5단계는 Phase 3.
- 추가 입양: 상점에서 아직 없는 시작 종을 포인트로 입양한다(초기값 300P). 새 펫은 1단계·초기 상태로 시작한다.
- 시작 종을 모두 입양하면 상점 펫 탭에는 '모두 함께하고 있어요'만 보인다.
- 활성 펫 교체와 이름 변경은 상점 '펫' 탭의 보유 펫 목록에서 한다. 활성 펫이 아닌 펫은 상태가 변하지 않는다. 비활성 기간은 감소 계산에서 뺀다(교체할 때 갱신 시각을 다시 잡는다).

### 3.4 날짜 넘김 처리
- 앱을 열 때(그리고 앱을 켜 둔 채 자정을 넘길 때) 마지막 처리일 다음 날부터 어제까지를 하루씩 처리한다.
  - 미완료 원타임 할일을 다음 날로 이월한다.
  - 미완료 반복 회차를 결석으로 기록한다.
  - 그날 해당하는 반복 할일이 있었는데 하나도 완료하지 않았으면, 프리즈가 있을 때 1개를 써서 그날을 프리즈로 채운다(3.6).
- 같은 날짜를 두 번 처리하지 않는다.
- 기기 시간 조작에는 대응하지 않는다(1인용 로컬 앱).

### 3.5 펫 그래픽 (개발 시점 AI 생성)
- 그래픽은 개발할 때 AI 이미지 생성으로 만들어 앱에 넣는다. 앱은 실행 중에 AI를 호출하지 않는다.
- 스타일: 매끈한 2D 일러스트(둥근 형태, 따뜻한 갈색 외곽선, 파스텔 색). 배경은 투명 PNG.
- 종·성장 단계마다 시트 1장(1행 × 4칸, 칸당 512×512): `기본 | 눈 감음 | 기쁨 | 배고픔`.
- 표정 선택 순서: 배고픔 30 이하 → 배고픔 칸, 기분 70 이상 → 기쁨 칸, 그 외 → 기본 칸(눈 감음과 교대).
- 움직임은 코드로 만든다: idle은 위아래 흔들림, 탭 반응은 기쁨 칸 + 점프, 3단계는 좌우 이동(방향에 따라 그림 좌우 반전, 찌그러졌다 펴지기로 걷는 느낌). 걷기 프레임은 만들지 않는다.
- 입양 펫도 시작 종 그림을 그대로 쓴다. 그림이 아직 없는 단계는 바로 아래 단계 그림을 쓴다.
- 배경·소품·프리즈 그림도 같은 방식으로 만든다.
- 생성 규칙·프롬프트는 `docs/ART_PROMPTS.md`, 출처는 `ASSETS.md`.

### 3.6 습관·스트릭
- 습관 = 반복 할일. 습관 화면에는 삭제하지 않은 반복 할일만 보인다.
- 잔디·달력의 지난 날은 회차 기록(완료·결석·프리즈)으로만 그린다. 기록이 없는 지난 날은 '해당 없음'. 반복 요일 계산은 오늘과 앞으로에만 쓴다.
- 출석 스트릭: 반복 할일을 하루 1개 이상 완료한 날이 이어진 일수. 프리즈를 쓴 날도 이어진 것으로 본다. 그날 해당하는 반복 할일이 하나도 없던 날은 끊지도 늘리지도 않는다.
- 습관 스트릭: 습관마다 해당 회차를 연속으로 완료한 횟수(해당 없는 요일은 건너뜀). 프리즈는 습관 스트릭을 보호하지 않는다.
- 오늘 아직 완료하지 않았으면 현재 스트릭은 어제까지로 계산한다(오늘 때문에 끊겨 보이지 않는다).
- 스트릭 보너스: 반복 할일을 완료할 때, 그 완료를 포함한 습관 스트릭이 3 이상이면 기본 포인트의 +10%, 7 이상 +25%, 30 이상 +50%(내림). 일일 상한에 포함한다.
- 프리즈: 상점에서 50P에 산다. 최대 2개까지 보관한다. 날짜 넘김 때 자동으로 쓴다(3.4).
- 습관 상세의 이번 달 달성률 = 이번 달 완료 회차 / (완료 + 결석) 회차.

### 3.7 3단계 성장
- 애정도 150 이상이면 3단계가 된다. 단계는 내려가지 않는다.
- 단계는 먹이·탭 때뿐 아니라 펫 상태를 읽을 때도 다시 계산한다(기준이 바뀌어도 바로 반영).
- 3단계는 홈 맵 바닥을 따라 천천히 좌우로 걸어 다닌다. 탭 반응은 그 자리에서 한다.
- 홈 애정도 게이지는 다음 단계까지 남은 양을 보여주고, 마지막 단계면 숫자만 보여준다.

### 3.8 상점·꾸미기
- 상점은 탭으로 나눈다: 먹이 / 배경 / 소품 / 프리즈 / 펫. 탭마다 그 상품만 보여준다. '입양' 대신 '펫'이라고 부른다.
- 배경: 홈 맵의 바탕으로 1개 장착한다. 일반 3종, 200~300P.
- 소품: 홈 '꾸미기'에서 보유 소품을 골라 홈 맵 위 원하는 곳에 놓는다. 놓은 뒤 끌어서 옮기거나 목록으로 되돌린다. 위치는 맵 크기에 대한 비율로 저장해 화면 크기가 달라도 같은 자리에 보인다. 일반 4종, 60~120P(예: 방석·화분·장난감·쿠션). 펫은 소품 위에 그려진다.
- 같은 배경·소품은 한 번만 산다. 장착·배치·해제는 언제든 무료.
- 따로 보관함 화면은 두지 않는다. 홈 '꾸미기': 보유 배경 장착·해제, 보유 소품 놓기·옮기기·되돌리기. 상점 '펫' 탭: 입양, 보유 펫 교체·이름 변경. 프리즈 탭: 보유 개수.
- 아이템 구매도 PointHistory에 기록한다(사유: 아이템, 아이템 id).

### 3.9 알림
- 종류와 기본 시각: 아침 08:00 오늘 할일 등록 유도 / 저녁 21:00 미완료 할일이 있을 때만 리마인드 / 습관 위기 20:00 출석 스트릭이 3일 이상인데 오늘 완료한 반복 할일이 없을 때.
- 하루 최대 3건. 펫이 말을 거는 말투로, 죄책감보다 반가움 톤.
- 설정에서 종류별로 켜고 끄고 시각을 바꾼다.
- 앱을 열 때와 할일을 완료·추가·취소할 때마다 앞으로 7일치를 하루 1건씩 예약하고, 오늘 조건이 사라진 알림은 오늘 것만 취소한다.
- 권한: Android 알림 권한(POST_NOTIFICATIONS)만 요청한다. 첫 완료 보상 안내 직후 1회 묻고, 거절하면 설정에서 다시 켤 수 있다. 정확한 시각 알람 권한은 쓰지 않는다(몇 분 늦게 울릴 수 있다).

### 3.10 통계
- 홈에서 들어간다.
- 이번 주(월~일)·이번 달 습관 달성률 = 완료 회차 / (완료 + 결석) 회차. 막대그래프로 날짜(주)·주(월)별 표시.
- 원타임·체크리스트는 기간 안에 완료한 개수로 따로 보여준다.
- 카테고리별 완료 수 비중(카테고리 없음 포함).
- 이번 주 획득 포인트 = 이번 주 완료 지급 − 취소 차감.
- 펫 한마디: 달성률 구간별 고정 문구.

### 3.11 설정
- 알림: 3.9.
- 글씨 크기: 휴대폰 설정 따름(기본) / 작게 / 보통 / 크게 / 아주 크게. 앱 전체 글씨에 적용한다.
- 화면 테마: 휴대폰 설정 따름(기본) / 밝게 / 어둡게. 펫·아이템 그림은 테마와 상관없이 그대로 보인다.
- 데이터 내보내기: 모든 데이터(할일·포인트·펫·아이템·설정)를 파일 하나로 저장해 다른 곳(파일 앱·드라이브 등)에 보관할 수 있게 한다.
- 데이터 가져오기: 내보낸 파일을 골라 지금 데이터를 통째로 바꾼다. 바꾸기 전에 두 번 확인한다. 이 앱이 만든 파일이 아니거나 더 새 버전 앱에서 만든 파일이면 거절한다.
- 데이터 초기화: 모든 데이터를 지우고 온보딩부터 다시 시작한다. 두 번 확인하고, 내보내기를 먼저 권한다.
- 정보: 오픈소스 라이선스, 그림 출처, 앱 버전.

## 5. 불변식
절대 깨지면 안 되는 규칙. CLAUDE.md 프로젝트 구역에도 옮겨 적는다.
- 포인트 지급과 사용은 이력에 기록하고 중복 지급하지 않는다.
- 활성 펫은 한 마리이며 교체해도 각 펫의 성장 상태를 보존한다.
- 기분·배고픔이 낮아져도 질병·죽음 페널티를 주지 않는다.
- 미완료 원타임 할일은 다음날 이월하고, 반복 습관은 결석으로 기록한다.
- 일일 기준은 현지 자정 00:00으로 한다.

## 6. 데이터 모델
DB(Drift)에는 사용자 데이터만 둔다.
- Todo: 종류(원타임·반복·체크리스트), 제목, 난이도, 카테고리, 날짜 또는 반복 요일
- ChecklistItem: 체크리스트 하위항목과 체크 여부
- TodoOccurrence: 할일 + 날짜 + 상태(완료·결석). 포인트 중복 지급 방지 기준
- PointHistory: 금액(음수 포함), 사유, 관련 회차, 아이템, 시각
- Pet: 종, 이름, 단계, 애정도, 기분, 배고픔, 마지막 갱신 시각, 오늘 탭 횟수
- UserProfile: 활성 펫, 마지막 날짜 처리일, 온보딩 완료 여부
- UserItem (Phase 2): 보유 아이템(종류: 배경·소품·프리즈, 아이템 id, 수량, 배경 장착 여부)
- PlacedItem (Phase 2): 맵에 놓은 소품(아이템 id, 가로·세로 위치 비율)
- 앱 설정 (Phase 2): 글씨 크기, 테마
- StreakFreeze (Phase 2): 프리즈를 쓴 날짜
- 알림 설정 (Phase 2): 종류별 켜짐·시각, 권한을 물었는지
- 스트릭·달성률은 저장하지 않고 회차 기록에서 계산한다.

종(PetSpecies)·먹이(FoodItem)·카테고리(Category 8종)·배경·소품·프리즈 목록은 코드 상수로 둔다.
기획서의 PetEvent, PetBehaviorProfile은 후속 Phase에서 구체화한다.

## 7. 화면 목록
- 하단 탭: 홈·할일·상점·설정

- 할일: 오늘·캘린더·습관·완료 보기, 등록·수정 화면(+ 버튼), 습관 상세(월별)
- 상점: 먹이·배경·소품·프리즈·펫 탭
- 설정: 알림(종류별 켜기·시각), 글씨 크기, 화면 테마, 데이터 내보내기·가져오기·초기화, 정보(라이선스·그림 출처·버전)

- 온보딩: 펫 선택 → 이름짓기 → 첫 할일 등록 → 첫 완료 보상 안내(직후 알림 권한 요청). 첫 할일을 등록하기 전에 앱을 끄면 다시 열 때 처음부터

## 8. 기술 결정 요약
상세는 `docs/decisions.md`.
Flutter, Riverpod, Drift/SQLite, 로컬 우선, 한국어 우선. 펫 그래픽은 개발 시점 AI 생성 정적 에셋(2D 일러스트 1×4 표정 시트 + 코드 모션), 런타임 AI 호출 없음. Flutter 3.44.8 / Dart 3.12.2. Phase 1은 Android로 개발·검증하고, iOS 빌드는 Mac 환경에서 이후에 한다. Phase 2는 DB 스키마 v2(마이그레이션)와 로컬 알림 패키지, 데이터 내보내기·가져오기용 파일 저장·선택 패키지가 필요할 수 있다(도입 전 비교·승인).

## 9. 미확정 사항과 위험
- Android/iOS 동시 출시 여부와 최소 OS 버전
- AI 이미지 생성 도구의 상업 이용 조건 확인 (출시 전)
- 시간대 이동 시 일일 기준 처리
- 수치(감소량·먹이 가격·성장 기준·입양 가격·보너스·아이템 가격)는 초기값이며, 실제로 써 본 뒤 조정한다
- 배경·소품 이름과 디자인 (그림 프롬프트 단계에서 정함)
- 위험: 로컬 전용이라 앱을 지우면 데이터가 사라진다. 직접 내보낸 파일로만 되살릴 수 있다(자동 클라우드 백업은 Phase 3.5~4)
- 위험: 7일 넘게 앱을 열지 않으면 알림이 멈춘다(예약을 앱을 열 때 갱신하므로)
